# Creator clipping for independent channels

Use this workflow for gaming clips and podcast excerpts supplied by the human operator. Each channel uses its own identity, account, audience goals and reporting. Keep app campaign assets, calls to action and activation metrics out of independent channel briefs.

Use the [creator clip brief](../templates/creator-clip-brief.md) and the [decision-rights matrix](../workforce/ownership-matrix.md). Track each handoff with a work item, one owner, a deliverable and a permission-safe evidence reference.

For a gaming upload that answers a specific player question, use the [gaming YouTube guide workflow](gaming-youtube-guides.md) to verify the steps and capture the proof.

## From recording to release

| Step | Accountable owner | Required evidence |
| --- | --- | --- |
| Choose and capture | Human operator | Manually press OBS Save Replay for the selected stream moment, or supply an authorized podcast recording. Provide the completed file through private storage and identify its source. |
| Check reuse scope | Partnerships Manager | Record the approval reference, allowed platforms, attribution, monetization, edit and duration limits, expiry and revocation terms. Route embedded third-party material for separate clearance. |
| Define the angle, when requested | Content Strategist | Audience, angle and intended channel outcome for the supplied moment. |
| Draft supporting text | Copywriter | Factual hook, title, description or commentary, with required attribution and credits. |
| Edit and check the final render | Video Producer | Exact output version, approved captions and creative QA. Decide the cuts, pace, speaker framing and audio mix. |
| Supply reusable tooling, when needed | Media Pipeline Engineer | Verified presets or integration, technical QA and source-to-output evidence. Any future file watcher observes completed exports without controlling OBS. |
| Create the static thumbnail, when needed | Graphic Designer | Channel-specific thumbnail with approved imagery and artwork provenance. |
| Review brand and accessibility | Brand Lead | Channel identity, safe areas, legibility, attribution and accessibility checks. |
| Approve release | Founder | Explicit approval of the exact final render, caption and metadata versions, thumbnail if applicable, verified destination channel, visibility and timing. |
| Upload or schedule | Social Manager | Verified account and approval scope, confirmed provider receipt and actual URL when published. |
| Measure | Growth Ops | Actual reach, retention, engaged views, subscriber change and per-clip costs with source, metric definition and date window. |

## Intake and rights

- Start from a human-supplied completed file. Keep automated discovery, downloads or capture outside this workflow. Preserve the source while editors and technical jobs use working copies or derivatives.
- Treat the source recording and permission to reuse it as distinct inputs. Obtain permission before editing material for reuse. Check third-party music, game/publisher terms where relevant, guest appearances, and other embedded media separately from creator permission. Hold the clip if a required permission is unknown, expired or outside the proposed use. The founder decides unresolved release questions with clearance evidence.
- Keep raw media, private transcripts, agreements and credentials in approved private stores. Use stable, non-sensitive references in the work item. Apply the agreed retention and scratch cleanup limits.

## Produce and review

- Use [creator-clip-edit](../skills/creator-clip-edit/SKILL.md) for the creative edit. Confirm game action or podcast speaker context survives the edit. Verify the actual rendered video, readable mobile captions, correct names and quotations, safe-area framing, dialogue levels, rights-required credits and target output format.
- Use [media-pipeline-automation](../skills/media-pipeline-automation/SKILL.md) only for technical work and rehearsals. Before a future live run, rehearse one short operator-supplied, permitted OBS clip and one short permitted podcast recording. Verify source preservation, completed-file intake, output, bounded storage and recovery from failure. Record missing samples or tooling as blockers.

## Release or hold

- Use the [publication and approvals policy](../policy/publication-and-approvals.md). A private or draft upload still sends a file externally and requires explicit permission. If the approved file, metadata, visibility, timing or channel changes, obtain approval for the updated package.
- Social verifies the specific account and independent channel before any upload. If the attempt is inconclusive, reconcile with the provider before retrying to avoid duplicates. Record the actual provider result and keep draft, scheduled and published states distinct. Use `work:publish` only once there is an approved work item and a verified published URL.
- The workspace supplies roles, checklists and a brief. Tool installation, credential configuration, watcher implementation and upload integration require separate technical work and approvals. Keep an offline package ready when connection or approval is pending.
