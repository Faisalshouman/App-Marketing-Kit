# Design Short-Form Videos

## Route the request

| Input | Work |
| --- | --- |
| Verified idea or selected clip | Design the hook, payoff, beats, and optional replay join. Preserve the existing evidence and cut boundaries unless the edit needs a change. |
| Raw link, long transcript, or factual brief with missing proof | Use the existing short-form clip-research workflow when available. If proof or timestamps remain unavailable, deliver conditional beats with their open dependencies. |
| Rough cut | Inspect playback or available frames and audio. Report the highest-impact actionable revisions and distinguish observed defects from suggested experiments. |
| Request to render | Use one available editor or renderer for the project. Pass it the approved beats and available assets. Report exactly what was rendered and inspected. |
| Request to explain posted performance | Use the existing research and analytics workflow when available. Tie each proposed edit to the observed problem and the matched comparison. |

Match the user's requested output. A request for hooks alone needs options and rationale. A production handoff needs timed beats. Use [Hooks and loops](references/hooks-and-loops.md) for opening choices and repeat viewing. Use [Production handoff](references/production-handoff.md) for shot design and machine-readable beats. Use [Review](references/review.md) for rough cuts, export, and controlled comparisons.

## Design the edit

1. Write the one thing the viewer can see, learn, or test on this watch. Identify the exact frame or audio moment that delivers it. Mark unverified claims, missing assets, rights, or source timestamps at the relevant beat. Preserve what the evidence demonstrates, including a forecast or simulation label when applicable.
2. Choose a first frame that makes sense without context and a short first line that gives the frame meaning. Put meaningful action, evidence, or a concrete clue in the first beat. Use two plausible openings only when a choice or comparison is useful. Describe what changes between them.
3. Time the video around the evidence and the viewer's reading pace. Specify the picture, spoken words, and on-screen text for each important beat. Keep a word or cut that is essential to the original speaker's meaning. Finish the answer on the first play.
4. Choose a replay join only when the second view gains a detail, a new interpretation, or satisfying continuity. Specify what happens at the end and at the start. Use a clean end when it better serves the story.
5. Use animation to show a change, relationship, scale, or mechanism. Label diagrams and reconstructions where viewers could mistake them for observed footage. Fit framing and captions to the intended platform and preview on a phone-sized frame. Choose local workflows and materials requiring no paid service by default. Keep publishing outside this skill's scope.

For a full brief, return the selected opening, the timed beats, the payoff, the exact end-to-start join or clean end, source and asset dependencies, and a concise editor review. Offer a JSON version when the user or a production agent needs structured input. If a finished cut is requested and the necessary tools and assets are available, render and inspect it before reporting completion.

When designing or reviewing a YouTube thumbnail or cover alongside the edit, use [YouTube thumbnail design and review](references/youtube-thumbnail-review.md) for title-image fit, device previews and test eligibility.
