# Product journey tutorial

Define the audience and first valuable outcome. Split the journey into tasks a user can recognize and complete. Every step should have a verified starting state, one clear action, an expected result, and a recovery path for common errors.

| Stage | User task | Prerequisites, plan and locale | Demo, text and accessibility | Success and recovery |
| --- | --- | --- | --- | --- |
| Evaluate | See a representative result | | | |
| Start | Reach the first useful result | | | |
| Repeat | Reuse or resume the workflow | | | |
| Expand | Use an advanced feature or approved adjacent product | | | |
| Recover | Resolve a common failure or find support | | | |

Link to approved destinations. For signed-in, paid, conditional or unavailable features, explain the exact prerequisite and provide a useful next action. A public walkthrough should use safe demo data. Record the product version, reviewer, review date and refresh trigger.
